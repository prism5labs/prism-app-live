# Prism 5 — standalone app

A complete rebuild of the Prism 5 app (the `prism-app-live` builder version,
live v9) as a standalone fullstack project, so we own every file and can
deploy it to GitHub and Render. No Muse artifact runtime, no
`@hatch/space-sdk`: plain Bun + TypeScript, zero runtime dependencies.

## What it is

A PWA named **Prism 5**. Four bottom tabs: **Chat, Inboxes, Store, Upkeep**.

- **Chat** is the front page: the Prism 5 Labs logo front and center, the
  app's display name (default "Prism 5", or the owner's custom name), and
  only the Photons the account owns, listed and tappable. An account owning
  nothing sees a plain "counter's empty" panel with Store and redeem paths.
  Chat and voice with an unowned Photon are refused server-side with a
  friendly note; nothing is saved and the meter is untouched.
- **12 Photons**: Prism, Juniper, Encore, Zero, Proof, Barnstormer,
  Blueprint, Calendra, Shopbell, Keystone, Vesper, Goldstar. Each has a
  saved chat thread and a persona. Prism is seeded from the self-export's
  SOUL and IDENTITY (see "Persona and privacy" below).
- **Chat** is real Claude-backed replies via the Anthropic API. 300 free
  chats a month per account; Upkeep ($29/mo) is unlimited chat plus updates,
  priority support, and live voice. The server enforces the meter and the
  gating. With no API key the app runs and answers honestly that the brain
  is not connected.
- **Store**: Supernova ($499 one-time, plus $49/mo, $39/mo 2-year, $539/yr),
  Satellite ($99 plus plans), each of the 12 Photons individually, Upkeep
  $29/mo, and the 23 Sparks & Plugs (Sparks $19/$25, Plugs $39/$59) grouped
  by category behind a Personal/Business toggle. Every Buy button opens
  that product's live Stripe checkout. All 55 URLs are byte-for-byte the
  live links in `~/workspace/business/stripe-payment-links.md`.
- **Upkeep**: redeem-code box, owned-status list, meter display, button
  into the Store. The friends-and-family code unlocks everything (all
  Photons, unlimited chat, all products shown as Owned); Upkeep stays a
  separate paid extra.
- **Inboxes**: reads all three Gmail accounts side by side (personal, Labs
  contact, Labs test) and can save real drafts into any account's Gmail
  drafts. Needs a Google OAuth client (see below); without one it says so
  honestly.
- **Make it yours**: the owner names their assistant on the front page;
  the name is stored server-side and replaces "Prism 5" as the displayed
  name until cleared.
- **Voice**: a "Call · Upkeep" button per Photon. Without Upkeep the server
  returns `needs_upkeep` with the $29 line. Live audio is not wired
  (ElevenLabs deferred); the gate and the UI are.
- **Look**: diner palette C (cream, teal, cherry, butter, ink), 24px
  corners everywhere, bottom nav buttons are true pills, chat bubbles keep
  a tail corner. No provider or model names in the visible copy.

## Stack

- Bun 1.4 + TypeScript. `bun:sqlite` for storage, `fetch` for the brain
  and Gmail. No npm runtime dependencies at all.
- Server: `src/server.ts` (Bun.serve). Serves `public/` and the JSON API
  under `/api/`.
- Client: `client/main.ts`, bundled by Bun into `public/main.js`.
  `public/styles.css`, `public/manifest.json`, `public/sw.js` (service
  worker: cache-first for the shell, network-first for the API).
- Icons: generated by `scripts/make-icons.ts` (gold triangle Pyramid mark
  on a teal field, PNG, no image library).
- Catalog: generated by `scripts/gen-catalog.ts` from the live Stripe
  links record and the product files, so the URLs are byte-for-byte exact.
  Do not hand-edit `src/shared/catalog.ts`; re-run the generator.

## Run it locally

```sh
bun install
bun run build        # client bundle + icons
bun run start        # serves on http://localhost:10000
```

For a scratch database: `DATA_DIR=/tmp/prism-test PORT=3100 bun src/server.ts`.

Typecheck: `bun run typecheck`. Client render test (needs the server up):
`bun scripts/test-render.ts`. Mock-brain test server:
`bun scripts/test-mock-anthropic.ts` (port 3101), then start the app with
`ANTHROPIC_API_KEY=test-key ANTHROPIC_BASE_URL=http://localhost:3101`.

## Deploy (GitHub + Render)

This repo is meant to replace the contents of
https://github.com/prism5labs/prism-app-live (public, user `prism5labs`),
whose current HEAD is the old deploy package (commit 4536419). The Render
service `prism-app-live` (Web Service, Docker, Free plan) is Blueprint
managed by `render.yaml` in this repo.

```sh
# From this directory, after review:
git init && git add -A && git commit -m "Prism 5 standalone v1"
git remote add origin https://github.com/prism5labs/prism-app-live.git
git push -u origin main --force   # replaces the old deploy package
```

Render auto-deploys on push. Set these in the Render dashboard (never in
the repo):

| Variable | What it does |
|---|---|
| `ANTHROPIC_API_KEY` | Turns chat on. Without it the app serves the shell and history, and new replies say the brain is not connected. |
| `ANTHROPIC_MODEL` | Optional. Default `claude-sonnet-4-5`. |
| `FREE_CODE` | Optional. Overrides the friends-and-family redeem code (default `2164039998`). Rotate the code by changing this, no code change needed. |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI` | Optional. Enable Gmail sign-in on the Inboxes tab. Without them the tab reports honestly that no accounts are connected. |
| `APP_URL` | Optional. Public base URL (used for the OAuth redirect). |
| `DATA_DIR` | Optional. Where the SQLite file lives. Default `./data`. |

### Free-tier limits (same as before)

- Sleeps after ~15 min idle; first open after a nap takes 30-60s.
- Ephemeral disk: chat history, unlocks, and Upkeep flags reset when the
  service redeploys or restarts. A persistent disk is a paid add-on.
- 750 instance hours/month; one always-on service fits.

## Persona and privacy

Prism is seeded from the self-export's SOUL and IDENTITY (her character,
style, and working rules), distilled in `src/server/personas.ts`. The
self-export's private memory (Neil's address, date of birth, health,
family details, license codes) is **not** copied into this repo and never
goes into the image. The deployed Prism starts with her persona, not the
Original's private memory. `/api/seed` reports `seeded: false` with that
note, matching the builder version's surface.

If a deployment should carry the full private seed, inject it server-side
(an env var or a file outside the repo), never by committing the export.

## API (for reference)

- `GET /healthz` → `{ ok, brain }`
- `GET /api/state?accountId=` → display name, owned Photons/products,
  meter, Upkeep, brain, Google status, Photon roster with owned flags
- `POST /api/redeem` `{ accountId, code }` → free code, server-side only.
  Wrong code: "That code doesn't match".
- `POST /api/custom-name` `{ accountId, name }` → set/clear the display name
- `GET /api/threads/:photon?accountId=` → saved thread
- `POST /api/chat` `{ accountId, photon, message }` → gating, meter,
  brain. Errors: `not_owned`, `meter_exhausted`, `brain_not_connected`.
  Nothing is saved and the meter is untouched on any error.
- `POST /api/voice` `{ accountId, photon }` → `needs_upkeep` (with the
  $29 line) or `voice_pending` (Upkeep on, live audio not wired yet)
- `GET /api/inboxes?accountId=` → the three Gmail accounts side by side
- `GET /api/oauth/google/start?accountId&label=` → Google sign-in
- `GET /api/oauth/google/callback?code&state=` → finishes sign-in
- `POST /api/inboxes/draft` `{ accountId, label, to, subject, body }` →
  saves a real draft into that Gmail account
- `GET /api/store` → the full catalog; `GET /api/seed` → seed status

Accounts are keyed by a device-generated id stored in localStorage and
sent as `X-Account-Id`. The server creates the account on first sight.

## Differences from the builder version (v9)

These are deliberate, and the parent should confirm them before the push:

1. **Photon portraits are placeholders.** The builder's 1950s superhero
   portraits are artifact assets and cannot be copied here. The app shows
   a generated tile (initial + triangle) and uses a real PNG the moment
   one is dropped in `public/photons/<Name>.png` (see that folder's
   README). Supply the portraits from the Labs site assets.
2. **Prism's persona is distilled, not the full self-export.** The private
   memory stays out of the public repo (see "Persona and privacy"). The
   builder version seeds from the full export inside the artifact.
3. **Tier copy is the builder app's wording (Nov 15, 02:35).** The website
   was later revised (Nov 15, ~04:30) with precision-language wording for
   the Supernova sentence and numbers-only stats for the lower tiers. The
   app was never confirmed to have picked that up. When Neil confirms the
   website wording is the app wording too, update `src/shared/tiers.ts`.
4. **Photon descriptions are written from the names + the broadened
   function rule.** The exact site copy for each Photon is not in a
   non-artifact file I could read. Pronouns: Prism, Encore, Proof,
   Blueprint, Juniper, Calendra she/her; Shopbell, Goldstar he/him
   (verified Nov 15). Zero, Barnstormer, Keystone, Vesper use they/them
   (no pronoun on record).
5. **License-code redemption is not in the app's redeem box.** The box
   takes the friends-and-family code only, matching the builder's known
   behavior. License codes are checked by the separate license-check page
   during install. The `owned` table already supports per-product
   ownership for when license redemption is wired in.
6. **Inboxes need a Google OAuth client.** There is none on file (same as
   the builder version). The OAuth flow, token refresh, message listing,
   and draft saving are built and the endpoints return the correct
   "not configured" states, but live Gmail was not testable without
   credentials. This is the one piece that needs a real OAuth client and
   a live sign-in test before it can be called done.
7. **No 15% Upkeep promo wiring.** The 15% rule (buy Upkeep with your
   first purchase, get 15% off while Upkeep stays active) is copy only;
   Stripe promo-code wiring is still open, same as the builder version.
8. **Gift flow is front-end only.** Gift-code issuance after a gift
   purchase is a backend step still to build, same as the builder version.
